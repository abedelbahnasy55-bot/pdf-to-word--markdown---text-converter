# خط الأنابيب — التفاصيل والقرارات

هذه المهارة مبنية على تجربة فعلية في تحويل مئات كتب PDF عربية إلى Word/PDF.
كل عتبة هنا ليست رأيًا، بل نتيجة قياس موثّق.

## ١. اختيار المسار: نصّ أم OCR؟

قبل أي OCR، افحص طبقة النصّ:

```bash
pdftotext -layout -enc UTF-8 book.pdf - | head
```

- **سليمة** إذا: ≥120 حرفًا/صفحة و≥25 كلمة/صفحة. استخدم النصّ مباشرة (أسرع وأدق).
- **تالفة أو غائبة** (مسح ضوئي، أو طبقة مشوّهة): استخدم Gemini OCR.

السبب: OCR دائمًا أقل دقة من طبقة نصّ أصلية، واستهلاكه للحصة بلا داعٍ خطأ.

## ٢. OCR: القطع والموديلات

| البند | القيمة | السبب |
|---|---|---|
| القطعة | **10 صفحات** | 36 صفحة تُنتج نصًّا قصيرًا/منهارًا |
| قطعة الإنقاذ | **6 صفحات** | تُستخدم تلقائيًا عند فشل بوابة الجودة |
| الموديل الأول | `gemini-3.5-flash-lite` ≈ 1ث/صفحة | الأسرع |
| موديلات التدوير | lite ← flash ← preview | لكل موديل حصة مستقلة |
| الحصة اليومية | **20 طلبًا/موديل** | مقاسة من رسالة 429 نفسها |

قائمة الموديلات الافتراضية (مُختبرة مع PDF):

```
gemini-3.5-flash-lite
gemini-3.1-flash-lite
gemini-flash-lite-latest
gemini-3.5-flash
gemini-flash-latest
gemini-3-flash-preview
gemini-3.6-flash
gemini-3.7-flash
```

> موديلات جيل 2.5 متقاعدة (404). `gemini-3.1-pro-preview` و`3-pro-image` حصتها صفر.
> `gemini-3.8-flash` مزدحم (503). `3.7-flash` بطيء جدًا (162ث/صفحة) ⇒ احتياطي أخير.

## ٣. البرومبت: عقد النسخ الحرفي

البرومبت في `assets/prompt_ocr.txt`، وأهم بنوده:

- الدور: «ناسخ ضوئي» لا محرّر.
- «كل سطر وكل كلمة وكل رقم».
- منع صريح: الحذف · الاختصار · التلخيص · إعادة الصياغة.
- `[؟]` عند الغموض بدل التخطي.
- فواصل صفحات `---PAGEBREAK---` لعدّ الصفحات.
- جداول Markdown كاملة، ومعادلات LaTeX.

كل بند في البرومبت يقابله فحص في بوابة الجودة؛ البرومبت مواصفة لا نصّ تحسيني.

## ٤. الاستئناف

- حالة لكل كتاب: `.pdf2book_work/<stem>.state.json`.
- كل قطعة تُحفظ فور نجاحها (نصّ + موديل + وقت).
- الكتابة ذرّية: ملف مؤقت + `os.replace`.
- إعادة التشغيل تكمّل من آخر قطعة، و`--force` يعيد من الصفر.
- عند نفاد الحصة: يُسجَّل الموديل في `dead_models` ويُبدَّل فورًا.

## ٥. التنظيف

| القاعدة | ماذا تزيل |
|---|---|
| ترويسات/تذييلات | سطر يتكرر في ≥50% من الصفحات (من أعلى/أسفل 3 أسطر) |
| أرقام صفحات | سطر يتكوّن من رقم فقط |
| آثار مسح | `CamScanner` · `PAGE BREAK` · `Screenshot` |
| أسطر مكسورة | دمج سطر prose لا ينتهي بعلامة ترقيم مع التالي |
| عناوين | `الباب/الفصل/المبحث/الدرس/الوحدة/المقدمة/الخاتمة` ⇒ `#`/`##` |

## ٦. بوابة الجودة

| المقياس | العتبة | يكشف |
|---|---|---|
| صفحات الناتج/الأصل | ≥ 0.85 | صفحات مفقودة |
| حروف/صفحة | ≥ 250 | حذف جماعي |
| نسبة الأسطر القصيرة | ≤ 0.28 | تفتّت OCR |
| سطور تشكيل مفرد | ≤ 20 | تدهور OCR |
| تكرار الأسطر | ≤ 0.15 | حلقات تكرار |
| تكرار الصفحات | ≤ 0.10 | صفحات معادة بالكامل |
| مواضع `[؟]` | ≤ 5 أو 1% | غموض OCR المتراكم (تحذير) |
| حروف لاتينية | ≤ 0.15 | تلوّث لغوي (تحذير) |
| وسوم متسرّبة | 0 | `---PAGEBREAK---` · `**` · `<u>` |
| جداول | أعمدة متساوية | جداول مكسورة |
| DOCX | فقرات > 20 + عربي + بلا وسوم | فشل البناء |
| PDF | صفحات > 0 | فشل التحويل |

## ٧. البناء

- محرّك `docx_engine.py` (نسخة من `arabic_docx.py`) ينتج Word RTL بأنماط:
  `ArTitle` · `ArH1` · `ArH2` · `ArBody` · صناديق · جداول · آيات.
- الخط: Amiri (عادي + عريض). إن لم يكن مثبتًا يظهر تحذير.
- PDF عبر LibreOffice بمجلد مستخدم مؤقت (`-env:UserInstallation`) لتجنب تعارض النسخ.
- يدعم `<u>نص</u>` في Markdown فيُخرج تسطيرًا حقيقيًا في Word.

## ٨. تشخيص قبل التحويل (`pdf_inspect.py`)

قبل أي OCR، شغّل التشخيص:

```bash
python3 pdf_inspect.py book.pdf --json report.json
```

يعرض: الصفحات · الحجم · حروف/كلمة لكل صفحة · نسبة العربي · نسبة الاستبدال ·
المسار المقترح (text/ocr) · القطع · عدد الطلبات المتوقّع · التنسيق (book/booklet).
هذا يمنع إهدار الحصة على كتاب له طبقة نصّ سليمة، ويكشف الملفات الضخمة قبل البدء.

## ٩. بنية ذكية (`structure.py`)

اختياري: يطلب من Gemini إضافة `#`/`##` فقط، دون تغيير أي حرف.

```bash
python3 pipeline.py book.pdf --out books --structure gemini
```

**التحقق:** يُزال كل `#` من الناتج ويُقارن النصّ بالأصل (`SequenceMatcher`)؛
إن كانت النسبة < 99.5% يُرفض الناتج ويُستعمل الأصل. النموذج `lite` يكفي.

## ١٠. LTR والكتب غير العربية

`--lang en` يمرّر `--ltr` لمحرّك Word: اتجاه لاتيني، خط LTR، بلا قواعد RTL.
بوابة الجودة تتوقّف عن اشتراط الحروف العربية، وتُبقي فحوص الصفحات/التكرار/الوسوم.

## ١١. الرياضيات (OMML)

| الخطوة | القاعدة |
|---|---|
| اكتشاف | وجود `$...$` ⇒ بناء pandoc تلقائيًا (`--math auto`) |
| الأرقام | ٠–٩ داخل الرياضيات ⇒ 0–9 (LibreOffice لا يعرض الهندية في OMML) |
| التوافيق | `{}^{ن}ق_{ر}` ⇒ `\binom{ن}{ر}` (يمنع المربعات الفارغة) |
| البناء | pandoc + `reference_rtl.docx` + `-M dir=rtl -M lang=ar` |
| الفحص | عدد `$...$` مقابل `<m:oMath>` في DOCX |

**حدود:** المصفوفات/التكاملات ذات الخطوط المنقّطة والترتيب البصري المعكوس قد تحتاج
مراجعة بشرية؛ النموذج قد يقلب ترتيب الحدود. اختبر 20–30 صفحة متنوعة قبل كتاب كامل.

## ١٢. ما لا يفعله

- لا يؤلّف محتوى ولا يلخّصه؛ ينقل ويخرّج فقط.
- لا يولّد فهرس TOC تلقائيًا.
- لا يصلح أخطاء OCR الدلالية (يتركها للمراجعة البشرية).
