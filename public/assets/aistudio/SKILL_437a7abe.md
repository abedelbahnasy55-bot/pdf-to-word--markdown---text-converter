# عربي PDF ← كتاب (Arabic PDF to Book)

مسار واحد يحوّل PDF عربيًا إلى **Markdown منظّف ← Word ← PDF**، مع بوابات جودة تمنع
الاعتماد على نصّ ناقص، ويصلح لأي مادة وأي كتاب.

## متى تُستخدم

- تحويل كتاب/مذكرة/بوكليت PDF إلى Word أو PDF قابل للطباعة والتعديل.
- دفعة كتب كاملة (مجلد PDF) مع تقرير نجاح/فشل لكل كتاب.
- إعادة بناء كتاب من مسح ضوئي رديء أو PDF بلا طبقة نصّ.
- توحيد كتب مادة واحدة بغلاف وعناوين وجداول واتجاه RTL.

## المدخلات والمخرجات

| المدخل | المخرج |
|---|---|
| ملف PDF أو مجلد PDF | لكل كتاب: `اسم.md` + `اسم.txt` + `اسم.docx` + `اسم.pdf` + `clean.json` + `qa.json` + `report.json` |

## التركيب بأمر واحد

```bash
curl -fsSL https://raw.githubusercontent.com/abedmohamed258/SKILLS/main/arabic-pdf-to-book/install.sh | bash
pdf2book inspect book.pdf
pdf2book convert book.pdf --out books/
```

> يعمل أيضًا محليًا: `PDF2BOOK_LOCAL_SRC=/path/to/skill bash install.sh`.

## التشغيل السريع

```bash
cd scripts

# ١) تشخيص سريع (طبقة نصّ؟ قطع؟ طلبات؟)
python3 pdf_inspect.py "/path/book.pdf"

# ٢) تحويل كامل
python3 pipeline.py "/path/book.pdf" --out "/path/books"

# ٣) مجلد كامل · تجربة جزئية · لغة إنجليزية
python3 pipeline.py "/path/pdfs" --out "/path/books"
python3 pipeline.py book.pdf --out out --pages 3
python3 pipeline.py book.pdf --out out --lang en

# ٤) بنية ذكية بالذكاء الاصطناعي (اختياري، مع تحقق 99.5%)
python3 pipeline.py book.pdf --out out --structure gemini

# ٥) استخدام نصّ خام جاهز (بدون OCR)
python3 pipeline.py book.pdf --out out --raw book.raw.md

# ٦) كتاب رياضيات: معادلات Word أصلية (OMML) تلقائيًا عند وجود $...$
python3 pipeline.py math.pdf --out books --math pandoc
```

## المسار (ببوابات)

1. **فحص الـPDF**: عدد الصفحات + هل له طبقة نصّ سليمة؟ (`pdftotext`)
   - سليمة (≥120 حرفًا/صفحة و≥25 كلمة) ⇒ استخراج نصّ مباشر بلا OCR.
   - ممسوحة ⇒ OCR عبر Gemini.
2. **OCR حرفي**: قطع **10 صفحات** (وتراجع إلى 6 عند فشل الجودة)، موديلات lite أولًا،
   تدوير عند نفاد الحصة، استئناف على مستوى القطعة.
3. **تنظيف**: حذف الترويسات/التذييلات المتكررة وأرقام الصفحات وآثار المسح،
   دمج الأسطر المكسورة، ترقية العناوين (`#`/`##`)، فحص الجداول.
4. **بناء**: محرّك RTL (Amiri · أنماط · جداول · آيات · شعر) ← DOCX ← PDF عبر LibreOffice.
5. **بوابة الجودة**: نسبة الصفحات، حروف/صفحة، الأسطر القصيرة، التشكيل المفرد،
   التكرار، تسرّب الوسوم، اتساق الجداول، سلامة DOCX/PDF.
   - فشل ⇒ إعادة OCR تلقائية بقطع 6 صفحات ثم إعادة البناء والفحص.

## البوابات الافتراضية

| البوابة | العتبة | لماذا |
|---|---|---|
| نسبة الصفحات | ≥ 85% من صفحات الأصل | كشف الصفحات المفقودة |
| حروف/صفحة | ≥ 250 | كشف الحذف الجماعي |
| الأسطر القصيرة | ≤ 28% | كشف التفتّت |
| التشكيل المفرد | ≤ 20 سطرًا | كشف تدهور OCR |
| التكرار | ≤ 15% | كشف الحلقات |
| وسوم متسرّبة | 0 | `---PAGEBREAK---` · `**` · `<u>` · ` ``` ` |
| الجداول | أعمدة متساوية | كشف جداول مكسورة |
| مسافات الترقيم | 0 مخالفة (قبل ،؛؟.! أو ملتصقة بعدها) | ضبط جذري لعلامات الترقيم |
| همزة الوصل/القطع | 0 (أي/إلى/إن/إذا/أبو/أحمد/أزهر) | رصد سقوط الهمزة |
| قفزات العناوين | 0 (## ← ####) | سلامة الهيكلة |
| DOCX/PDF | موجودان + فقرات عربية + PDF>0 | كشف فشل البناء |

`qa_gates.py` يطبع ✅/❌ لكل بند ويعيد **رمز الخروج**: 0 قبول · 1 فشل.

## إدارة مفاتيح Gemini (2.6)

الحصة المجانية: **20 طلبًا/يوم لكل موديل**، والطلب ≤10 صفحات. الاستراتيجية:

| المكوّن | السعة اليومية |
|---|---|
| مفتاح واحد × موديل واحد | 200 صفحة |
| مفتاح واحد × 8 موديلات | 1,600 صفحة |
| 5 مفاتيح × 8 موديلات | **8,000 صفحة** |
| محرّك Tesseract المحلي | بلا حد (fallback للكمّ الكبير) |

`keypool.py` يدير ذلك: يقرأ `GEMINI_API_KEY_1..N` أو `~/.config/ocr/gemini_keys`،
يوزّع الطلبات على (مفتاح × موديل) بعدل، يحفظ العدّاد ذرّيًا في `~/.cache/pdf2book/keypool.json`
ويصفّره يوميًا، ويميّز **429 حصة** (بدّل الخانة) عن **403 مفتاح** (اعزل المفتاح).

```bash
pdf2book keys      # كم صفحة يمكن تحويلها اليوم
```

قاعدة: لا تُهدر حصة على صفحة واحدة — القطعة المثالية **10 صفحات/طلب**، والإعادة عند
الفشل بقطع 6. عند نفاد كل الخانات: أكمل بـ`--ocr-engine local` بلا حصة ثم أعد المحاولة غدًا.

## تدقيق الاقتباسات (2.4)

`verify_quotes.py` يفحص أي ملف Markdown عربي ويُخرج ملاحظات مرمّزة (Q/H/T) بأرقام الأسطر:

```bash
bash scripts/fetch_corpora.sh            # مرة واحدة: ~20MB في ~/.cache/ar-verify
pdf2book fetch-corpora
pdf2book verify book.md --json out.json
pdf2book fix-quotes out.json            # يطبّق Q001/Q002/Q003/T001/T002/T004
pdf2book clean-structure books/         # ترويسات متسرّبة · ** مفرد · تكرار فوري
```

| الرمز | المعنى | المصدر |
|---|---|---|
| Q001 | نصّ آية مخالف (حرف/كلمة) | quran-simple |
| Q002 | تشكيل مخالف | quran-simple |
| Q003 | مرجع خاطئ مع اقتراح الصحيح | مطابقة عالمية |
| Q004 | آية بلا مرجع | — |
| Q005 | اقتباس متعدد الآيات (معلومة) | دمج آيتين |
| H001 | حديث غير موجود في البخاري/مسلم | fawazahmed0 (Unlicense) |
| H002 | نصّ حديث مخالف | نفسه |
| T001…T010 | أقواس `{}` · أشكال عرضية/فارسية · «» غير متوازنة · مسافة قبل ترقيم · `**` · جدول · عنوان مكرر · سطر طويل · سطر مكرر | قواعد نصّية |

**قواعد الاستخدام:**
1. المرجع الملزم للآيات هو `quran-simple` (إملائي كامل التشكيل) — لا تخلطه بـ`qpc-hafs` العثماني.
2. الاقتباس الجزئي ليس خطأ؛ Q005 معلومة لا خطأ.
3. حديث غير موجود في الصحيحين ≠ خطأ (قد يكون في كتاب آخر) — صنّفه «غير محقق».
4. `--fix` يصلح الأقواس والمسافات فقط، ولا يمسّ نصّ آية.

الوكيل `مدقق_الاقتباسات` (subagent بموديل `deepseek-v4.1-flash-1017`) يشغّل الأداة ثم يراجع
الملاحظات غير الحاسمة (حديث/شعر/مرجع غامض) ويعيد جدولًا بأدلة.

## تخطيط الأسئلة والخيارات (2.1)

أكثر عطل متكرر في بوكليتات OCR: **الاختيارات لازقة في السؤال أو في بعضها**، لأن المصدر
يكتب الخيارات متتابعة في سطر واحد بنمط `-١ … -٢ …` (شرطة قبل الرقم، نمط الكتب المصرية)،
أو `١- … ٢- …`، أو يخلط النمطين.

- `explode()` يفصل **أي نمط وأي ترتيب** إلى سطر مستقل لكل خيار، ويحذف الفاصلة/النقطة الختامية.
- رقم البند/الحرف يُتبع بـ`NBSP` حتى لا يلتصق بالآية أو النصّ في Word.
- فجوة تلقائية بين `﴾` والمرجع `[...]`، وبين `]` والآية التالية.
- الأقواس المعقوفة `{…}` تُوحَّد إلى `﴿…﴾` قبل البناء.

**قبل البناء** افحص المصدر: سطر فيه أكثر من علامة خيار = عطل قادم.
```bash
python3 - <<'PY'
import re
M = re.compile(r"(?:^|(?<=[\s.،]))(?:-([٠-٩\d]{1,2})|([٠-٩\d]{1,2})-)\s+")
for i, l in enumerate(open("book.md", encoding="utf-8"), 1):
    if len(M.findall(l)) >= 2:
        print(i, l[:90])
PY
```

## قواعد ذهبية (مُثبتة بالتجربة)

1. **القطعة الصغيرة أفضل**: 36 صفحة تُنهي الجودة؛ 10 هي الافتراضي و6 للإنقاذ.
2. **البرومبت عقد**: النسخ الحرفي 100%، `[؟]` عند الغموض، لا تلخيص ولا حذف.
3. **lite أولًا**: `gemini-3.5-flash-lite` ≈ 1ث/صفحة، و`3.7-flash` ≈ 162ث — احتياطي فقط.
4. **الحصة 20 طلبًا/يوم/موديل** (لا 1500): التدوير على الموديلات هو الحل.
5. **429 نوعان**: نفاد حصة ⇒ تبديل فوري؛ تجاوز معدل ⇒ انتظار وتراجع.
6. **رد فارغ عابر ≠ موديل ميت**: أعد المحاولة 3 مرات قبل الاستبعاد.
7. **الاستئناف ذرّي**: اكتب الحالة إلى ملف مؤقت ثم `os.replace`.
8. **لا تعتمد على OCR وحده**: بوابة الجودة هي الفيصل، وأي فشل يعيد التحويل بقطع أصغر.

## ١.٣) الرياضيات (OMML)

- عند وجود `$...$` يتحوّل البناء تلقائيًا إلى **pandoc** ⇒ معادلات Word أصلية قابلة للتحرير.
- الأرقام العربية-الهندية داخل الرياضيات تُحوَّل إلى غربية (LibreOffice لا يعرضها في OMML).
- تدوين التوافيق `^{ن}ق_{ر}` يُحوَّل إلى `\binom{ن}{ر}` (يمنع المربعات الفارغة).
- تحقق البوابة: عدد تعبيرات `$...$` مقابل عدد `<m:oMath>` في DOCX؛ فشل إذا صفر.
- الحدود: المعادلات المرسومة بخطوط منقّطة أو المصفوفات المعقّدة تحتاج مراجعة بشرية؛ OCR يقرأ الترتيب البصري وقد يقلبه.

## قاعدة ذهبية 9 — اسم الدرس على التدريبات (2.9.1)

كل قسم تدريبات في البوكليت يُسمّى: **## N. اسم الدرس الحقيقي من الكتاب — تدريبات صفحة X** (لا «الدرس N» أبدًا). تُستخرج الأسماء من صفحات «أهداف الدرس» في المصدر، وأرقام الصفحات من صفحات «التدريبات». المحرّك يعرض الاسم فقط (`## 1. النعت — تدريبات صفحة 17` ← «النعت — تدريبات صفحة ١٧»).

## الجديد في 2.9.0 (البلاغة + توحيد البناء — دروس جولة العربي)

- **بنود «س٢:»**: البند المرقّم تحت سؤال موسوم بـ«س٢:» فرع/خيار له، لا سؤال رئيسي جديد (`s_main`) — يُنهي عطل «كل بند فعلَ تكليف صار سؤالًا رئيسيًا» في البلاغة والأدب. له اختبار انحدار (`SMainRenderTests`).
- **استخراج كتل التدريبات**: حدِّد صفحات «التدريبات» في المصدر (ابحث بـ`pdftotext` عن «التدريبات»/«أهداف الدرس»)، قصّ كل كتلة حتى «أهداف الدرس» التالية، ثم OCR الكتل فقط — لا الكتاب كله. البلاغة: 25 صفحة/10 كتل، النحو: 109 صفحات/12 كتلة.
- **التحقق النهائي**: `qa_gates.py` ‏PASS (0 فشل) + `verify_quotes.py` ‏(0 مفخّم Q001/Q003؛ تحذيرات تشكيل Q002 فقط) قبل التسليم — لا اعتماد على «تم البناء».
- **التكرارات**: مجلدات `بوكلتات/` المكررة حرفيًا من `بوكليتات/` تُنقل إلى `00_نسخ_احتياطية/` (تحقق MD5) — ممنوع الحذف المباشر.
- **التسليم**: انسخ DOCX/PDF إلى `00_التسليم/{Word,PDF}/` و`00_التسليم/حسب_المواد/` إن وُجدت — الوجهة Canonical كافية إن لم توجد.

## الجديد في 2.8.0 (بوكليت الصرف — دروس من الشكاوى الحقيقية)

- **تراتب البوكليت**: كشف السؤال الرئيسي بأفعال التكليف (مثل/أدخل/صغ/عين/يا...)، توحيد أسلوب الفروع (أ)–(ي)، `ArQuestion` عريض كحلي، و«نشاط (١):» كتعليمات — يُنهي عطل «الرئيسي والفرعي معجونان».
- **أقواس معكوسة**: إصلاح `)أ(` ← `(أ)` من طبقة نصّ InDesign + بوابة `no-reversed-parens`.
- **ترويسات**: تجميع الترويسات المتقاربة («الرصف امليرس» = «الصرف الميسر») فلا تتسرّب إلى المتن.
- **رياضيات وهمية**: فكّ `$\left\langle\text{آية}\right\rangle$` إلى `﴿﴾` وتطبيع الشرطة المضاعفة (`$\\checkmark$`) — كانت تُفشل بوابة المعادلات في الكتب غير الرياضية.
- **طبقة مقلوبة الحروف**: رفض طبقة نصّ نسبة `ا+حرف+ل` فيها ≥6% والتحوّل إلى OCR.

## سير العمل القياسي (إلزامي لكل ملف)

1. **الجرد**: حدّد المصدر الأصلي (PDF الكتاب) — لا تبنِ على `.md` قديم مجهول المصدر. سجّل عدد صفحاته وطبقة نصّه.
2. **التشخيص**: `pdf2book inspect` — طبقة مقلوبة الحروف (`الرصف` بدل `الصرف`) تُرفض تلقائيًا وتُحوَّل إلى OCR.
3. **استخراج التدريبات/الأقسام**: قارن عدد أجزاء المصدر بعدّ عناوين «التدريبات» في الـPDF — لا تدمج ولا تُسقط قسمًا (بوكليت الصرف أسقط قسمًا كاملًا ودمج آخرين).
4. **OCR**: صفحات كثيفة التشكيل/الآيات بـ`gemini-3.5-flash` (لا lite — الـlite يألف آيات). القطعة 10 صفحات، والإعادة 6.
5. **الاكتمال**: قارن كل قسم بالمصدر — عدد الأسئلة الرئيسية، الفروع (أ)–(ي)، صفوف كل جدول، وأنشطة (١)–(٤). أي نقص = إعادة OCR للصفحات الناقصة فقط (`--raw` + `--no-retry` لإعادة البناء بلا هدر حصة).
6. **التدقيق**: `pdf2book verify` للآيات/الأحاديث، ثم `fix-quotes`، ثم `clean-structure`.
7. **البناء والبوابة**: `pipeline.py` (أو `build_book.py --profile booklet`) — لا اعتماد إلا بـ`qa.json: PASS`.
8. **التسليم**: انسخ `.docx` + `.pdf` + `.md` إلى كل نسخ التسليم، واعمل نسخة احتياطية من القديم **قبل** الكتابة فوقه — ممنوع الحذف النهائي (النقل للأرشيف فقط).

## أخطاء شائعة (من بوكليت الصرف — لا تكرّرها)

| العطل | السبب الجذري | الإصلاح |
|---|---|---|
| `)أ(` أقواس معكوسة | طبقة نصّ InDesign بصريّة | `fix_reversed_parens` + بوابة |
| الرئيسي/الفرعي معجون | لا «س1:» في المصدر + أفعال ناقصة | `is_main_question` + `ArQuestion`/`ArSub` |
| خيارات ملتصقة | نمطا `-١` و`١-` مختلطان | `explode()` قبل البناء |
| جدول صف واحد | جدول ممتد على صفحتين + فاصل | `normalize_tables` عبر الفجوات |
| ترويسة «الرصف امليرس» | رسم مختلف كل صفحة | تجميع `norm_key` المتقارب |
| آيات مؤلَّفة | Gemini lite على آيات كثيفة | `gemini-3.5-flash` للصفحات الكثيفة |
| `$\left\langle\text{آية}\right\rangle$` | OCR يغلّف الآيات كمعادلات | `latex_clean` يفكّها إلى `﴿﴾` |

## English quick start

1. Install: `python3 -m pip install python-docx pypdf` + `poppler-utils` + LibreOffice + Amiri font.
2. Key: `~/.config/ocr/gemini_key`, or `GEMINI_API_KEY`, or `--key-file`.
3. Inspect: `python3 scripts/pdf_inspect.py book.pdf`
4. Convert: `python3 scripts/pipeline.py book.pdf --out books/`
5. Output: `books/<name>/<name>.md` · `.docx` · `.pdf` · `qa.json` · `report.json`.

Options: `--mode auto|ocr|text` · `--chunk 10` · `--structure gemini` · `--lang en` · `--raw raw.md`.

> The pipeline never rewrites content: OCR is verbatim, and AI structuring is rejected
> if text similarity drops below 99.5%.

## حدود معروفة

- لا يفهم محتوى الكتاب ولا يعيد تأليفه؛ وظيفته نقل وإخراج.
